IP Scanner

With the IP Scanner you can scan IP ranges, subnets and hostnames for active devices: a host is found if it answers the ping, a TCP port (open, or closed with a TCP reset), NetBIOS or SNMP; hosts in a local subnet that drop all of them (e.g. a firewall) are found by their ARP / NDP entry, see How hosts are found. For every host, the hostname (DNS, mDNS or NetBIOS), the MAC address and vendor and the open ports are shown, optionally also a guess of the operating system, the web page and the SNMP system information.

Example inputs​

HostDescription
10.0.0.1Single IP address (10.0.0.1)
10.0.0.100 - 10.0.0.199All IP addresses in a given range (10.0.0.100, 10.0.0.101, ..., 10.0.0.199)
10.0.0.100-199All IP addresses in a given range, shorthand for the last octet (10.0.0.100, ..., 10.0.0.199)
10.0.0.0/23All IP addresses in a subnet (10.0.0.0, ..., 10.0.1.255)
10.0.0.0/255.255.254.0All IP addresses in a subnet (10.0.0.0, ..., 10.0.1.255)
10.0.[0-9,20].[1-2]Multiple IP addresses like (10.0.0.1, 10.0.0.2, 10.0.1.1, ...,10.0.9.2, 10.0.20.1)
borntoberoot.netSingle IP address resolved from a host (10.0.0.1)
borntoberoot.net/24All IP addresses in a subnet resolved from a host (10.0.0.0, ..., 10.0.0.255)
borntoberoot.net/255.255.255.0All IP addresses in a subnet resolved from a host (10.0.0.0, ..., 10.0.0.255)
!10.0.0.1Excludes an IP address (also a range, subnet or host, e.g. !10.0.0.0/28) from the other inputs
note

Multiple inputs can be combined with a semicolon (;). A column pasted from Excel (one entry per line) is converted to the semicolon-separated form automatically.

An input starting with ! excludes its IP addresses from the other inputs, e.g. 10.0.0.0/24; !10.0.0.1; !10.0.0.200-254 (all formats of the table above; a hostname excludes all its IPv4 and IPv6 addresses, independent of the IPv4 preference). At least one input without ! is required; if the exclusions remove every IP address, a message is shown instead. If the hostname of an exclusion can't be resolved (also if only the IPv4 or the IPv6 lookup fails, e.g. a timeout), nothing is scanned (otherwise its IP addresses would be scanned).

Example: 10.0.0.0/24; 10.0.[10-20].1; 10.0.0.100-199

IP addresses that are part of multiple inputs (e.g. 10.0.0.1; 10.0.0.0/24) or entered with different hostnames (e.g. two names of one server) are scanned only once. The hostname is resolved via DNS (PTR), mDNS or NetBIOS, not taken from the input. The network and broadcast address of a subnet are scanned as well.

A scan of more than 65,536 IP addresses (e.g. a /15) must be confirmed, more than 16,777,216 IP addresses (a /8) cannot be scanned at once.

The Options button next to Scan opens a menu to turn the most used settings on or off without opening the settings: Ping hosts, Resolve hostname, Scan ports, Read Windows host information (beta), Scan for NetBIOS, Find hosts in the local subnet, Resolve MAC address and vendor, Resolve mDNS hostname, Read web pages (only with the port scan), Read the SNMP system information, Show unreachable IP addresses and ports and Expand host view. Open settings... opens the IP Scanner settings. The menu stays open to change several options and is disabled while a scan is running. The credentials section below the options shows the credentials of the tab: the SNMP version and credentials of the profile / group it was opened with (e.g. SNMP version and credentials of "Site A") and its Windows credentials (e.g. Windows credentials of "Site A" (CORP\admin) or Windows credentials of this tab (CORP\admin)). Set Windows credentials... (with Read Windows host information enabled) sets the Windows credentials of the tab, also for a tab without a profile (e.g. another admin account for one scan): they replace the ones of the profile / group (or, with Use credentials off, the user running NETworkManager is used), are used for all following scans of the tab (also Automatically scan every and Rescan) and are not saved - closing the tab discards them. Credentials that were rejected (see Windows account lockout protection) are checked again after they were set here (the logon failures already counted for the account stay counted).

The menu changes the settings: they apply to all tabs and are shown in the settings. Changes apply to the next scan (Expand host view immediately), like a change in the settings.

How hosts are found​

The probes of a host run at the same time. A host is shown (and counted as up) as soon as it answers the first one, probes that answer later are added.

ProbeAnswerSetting
PingICMP echo replyPing hosts
TCPA port is open or refused the connection (TCP reset)Scan ports
NetBIOSAnswer to the NetBIOS request (UDP 137, IPv4 only)Scan for NetBIOS
SNMPAnswer to the SNMP request (UDP 161)Read the SNMP system information
ARP / NDPNeighbor entry of a host in a local subnet that didn't answer any of the probes aboveFind hosts in the local subnet

The probes a host answered are shown in the tooltip of its status icon (e.g. Up (detected by Ping, TCP)) and as status icons in the headers of the row details. The export contains them as DetectedBy (e.g. ICMP, TCP or ARP).

Only reachable hosts are shown, unless Show unreachable IP addresses and ports is enabled; unreachable hosts are added when all their probes are finished.

Result​

The number of reachable (up) and unreachable (down) IP addresses is shown below the Result header. A message below the input is shown if no reachable host was found, the scan was canceled, a hostname could not be resolved or an error occurred.

The columns are shown according to the settings the scan was started with, settings changed afterwards apply to the next scan:

ColumnContent
StatusUp / down, the tooltip shows the probes that answered
RoleIcon if the host has a role for this computer: This computer, Default-Gateway, DNS server or DHCP server of a connected network interface (all roles in the tooltip)
Since last scanChange since the previous scan, see Changes since the last scan (only if the result is compared with one)
IP addressScanned IP address
HostnameDNS hostname (PTR), otherwise the mDNS hostname, otherwise the NetBIOS name
TimeRound trip time of the ping reply
OSWindows version (e.g. Windows 11 25H2, edition and version number in the tooltip) if it was read, see Read Windows host information, otherwise the operating system guessed from the TTL of the ping reply, see Guess the operating system from the TTL
Open portsOpen ports (e.g. 22, 80, 443), the tooltip shows them with their service (e.g. Open: 22 (ssh), 443 (https), the first 10); sorted by the number of open ports
DomainDomain (DNS name) or workgroup of the Windows host information, otherwise the workgroup / domain of the NetBIOS answer (shown with Read Windows host information or Scan for NetBIOS)

Values arrive one after another while the scan is running:

  • ...: the probe or lookup is still running. Hostname and MAC address / Vendor stay ... until no source can change them any more (e.g. the NetBIOS name as fallback), Web until the port scan is finished (it needs the open ports), Windows until the port scan is finished if port 445 is in its ports (not after the other probes).
  • -/-: finished, no result.
  • After Cancel, the lookups that were still running (hostname, MAC address, mDNS, web page, Windows) show -/-; ping, ports, NetBIOS and SNMP that didn't finish stay ....

A column you sorted by is not sorted again for values that arrive later, click the header again. Sorted by Time or MAC address, hosts without a value are always at the end; hosts with the same value are sorted by IP address.

The search box right of the Result header filters the results by IP address, hostname (DNS, mDNS, NetBIOS), MAC address, vendor, role, OS (guess), web page (title, headers, realm, redirect target, certificate), SNMP values, Windows values (operating system, version number, edition, computer name, domain, description, logged-on users) and open ports (number or service), also while the scan is running. Export... > all exports the filtered results; the up / down counters always count all hosts. Results can also be exported while the scan is running, values that are still ... are exported as empty values.

Changes since the last scan​

A scan of the same input as the last completed scan in the tab shows what changed since then:

  • New: the host is up now, it was not up in the last scan.
  • Gone: the host was up in the last scan, it is not up now. The row is added at the end of the scan (as down, with the hostname and MAC address of the last scan), also if Show unreachable IP addresses and ports is disabled.
  • MAC changed: the host is up with another MAC address than in the last scan (both known), e.g. a replaced device, an IP address conflict or ARP spoofing. The tooltip shows the previous MAC address.

The Since last scan column and the counters below the Result header (e.g. 2 New · 1 Gone) are only shown if the result is compared with a previous scan. Last scan at in the header shows when the last scan was completed (the tooltip shows the date).

Only completed scans are compared: a canceled scan or a scan with another input starts over (the next scan of this input is compared with it). Rescan of selected hosts updates their rows and their changes against the same previous scan (e.g. a gone host that is up again), but is not a scan of the input. The last scan is only kept in memory, as long as the tab is open. The change is also in the search and the export (Change, PreviousMACAddress).

Repeat the scan​

Automatically scan every right of the Result header repeats the scan after the selected interval (1 min to 1 h, the pause after a scan, so scans don't overlap) - e.g. to watch a network for new devices, see Changes since the last scan. The repetition starts with the next completed scan; while it waits, the header shows the countdown (Next scan in 04:32, the tooltip shows the last scan).

A repeated scan keeps the rows and updates them in place (selection, scroll position, expanded details and search stay): new hosts are added, hosts that are down now are shown as Gone. The input is not asked to be confirmed again (large scans) and is not added to the history again.

The repetition stops when a scan is canceled, the input is changed (also while a scan is running) or the tab is closed; a manual Scan starts the interval again after the scan. If a repeated scan fails (e.g. a hostname can't be resolved for a moment), the message is shown and the scan is tried again after the interval, so a short network problem doesn't end the monitoring. The scan is also repeated while another tab or application is shown. The checkbox is per tab and not saved (a new tab doesn't repeat), the interval is saved.

Ping hosts​

Send a ping (ICMP echo request) to every IP address. Disable it if ICMP is blocked or rate limited in the network (e.g. by an IDS): without ping, an unreachable host is finished after the port scan / NetBIOS timeout instead of after all ping attempts, so the scan is faster. Hosts that only answer the ping are not found then. The Time column and the ping details are hidden for a scan without ping.

Type: Boolean

Default: Enabled

note

A host is only found if it answers a probe: at least one of Ping hosts, Scan ports, Scan for NetBIOS or Read the SNMP system information must be enabled, otherwise the scan doesn't start. Find hosts in the local subnet alone is not enough, it uses the neighbor entries created by the packets of these probes.

Attempts​

Maximum number of ICMP requests sent to each IP address. Another request is only sent if the previous one has timed out (e.g. a lost packet), other replies like "destination host unreachable" are final.

Type: Integer [Min 1, Max 10]

Default: 2

Timeout (ms)​

Timeout in milliseconds for each ICMP request, after which the packet is considered lost.

Type: Integer [Min 100, Max 15000]

Default: 2000

Buffer​

Size of the buffer for each ICMP request in bytes.

Type: Integer [Min 1, Max 65500]

Default: 32

Guess the operating system from the TTL​

Shows the operating system guessed from the TTL of the ping reply in the OS column (icon and text, ... while the ping is running; the Windows version replaces it if it was read with Read Windows host information): every operating system starts with a typical TTL and every router on the way reduces it by one. The guess is the smallest typical TTL that is not lower than the received TTL, the tooltip shows the number of hops (e.g. TTL 126 → Windows, 2 hops). No additional packets are sent.

Initial TTLOS (guess)IconExamples
64Linux / UnixTerminalLinux, macOS, Android, iOS, many IoT devices
128WindowsWindows logoWindows
255Network deviceSwitchRouters, switches, printers, Solaris

Type: Boolean

Default: Enabled

note

It's a hint, not a detection: the TTL can be changed on the host (e.g. some devices use 64 or 128), NAT and VPN can change it. Only available for hosts that answered the ping and only for IPv4 (the ping reply of IPv6 has no TTL). The export contains it as OSGuess (LinuxUnix, Windows, NetworkDevice).

Timeout (ms)​

Timeout in milliseconds after which a port is considered timed out (no answer). A port is closed if the host refused the connection.

Type: Integer [Min 100, Max 15000]

Default: 2000

note

A closed port is reported as soon as the host refuses the connection. Each attempt sends the connection request once (see Attempts).

Attempts​

Number of connection requests sent to each port. Another request is only sent if there was no answer (timed out), an open or closed port is final.

Type: Integer [Min 1, Max 10]

Default: 1

tip

In a local network (LAN), 1 is enough. On an unreliable network (e.g. Wi-Fi, VPN) or for hosts on the internet, a lost connection request can make an open port appear as timed out and a host appear as unreachable - increase it to 2 in this case. This only takes longer for ports without answer (attempts × timeout); with the default settings, unreachable hosts are not slower up to 2 attempts, because the ping takes as long (2 × 2000 ms).

Read Windows host information​

Beta

This setting is in beta (Beta label in the settings and the Options menu): it is tested publicly and may change. Turn it off to stop all SMB requests and logons of the scans (also of Rescan). Please report problems on GitHub.

Read the Windows host information of every reachable host over SMB (TCP port 445). With Scan ports enabled and port 445 in its ports, only hosts with port 445 open are asked, otherwise every found host (a host without SMB is finished after the SMB request).

Two steps, the second only if the host answered the first:

StepCredentialsValues
SMB / NTLM negotiationNone (no logon, no failed logon on the host)Operating system and build (e.g. Windows 11 25H2, 10.0.26200), computer name, domain, time offset to the local clock, SMB version and signing
NetApi (RPC over SMB)User running NETworkManager, or the Windows credentials of the profile / group the tab was opened with or of the tab (Options > Set Windows credentials...)Role (workstation, server, domain controller), description, workgroup; with admin rights on the host also the logged-on users and, if the Remote Registry service runs, the patch level, display version and edition (e.g. Pro, 10.0.26200.6584)

The NetApi requests connect to the DNS hostname of the host if it is the full DNS name the host sends itself in the NTLM negotiation (Kerberos), otherwise to the IP address (NTLM, e.g. a computer in a workgroup). With Windows credentials, hosts that are not part of the lockout protection (workgroup computers, local accounts) are always asked by their IP address. Errors (e.g. Access is denied., wrong password) are shown in the row details instead of the values. The values are in the search and the export (WindowsOS, WindowsEdition, WindowsVersion, WindowsRole, WindowsComputerName, WindowsDomain, WindowsTimeOffset in seconds, WindowsUsers, WindowsDescription, WindowsError as Win32 error code, -1 if not tried because the credentials were rejected on another host (or by this host in an earlier scan of the tab), -2 if not tried because they were still being checked on another host after the timeout, SMBDialect, SMBSigningRequired, SMBServerGuid).

Type: Boolean

Default: Disabled

note

Windows 10 / 11 and Windows Server 2016 and later all report the version 10.0, the build tells them apart. Some builds are shared by a client and a server version (e.g. 26100: Windows 11 24H2 / Server 2025), the role decides if it could be read. Hosts that only allow Kerberos (NTLM disabled) don't send the NTLM values; Samba and NAS devices answer with their own values (no Windows version).

note

With the Windows credentials of a profile / group / tab, a wrong password must not lock the account (every host in a domain makes a domain controller count a failed logon). The credentials are checked on one host at a time until a Windows host in the domain of the credentials accepts them; after a failed logon in their domain (or without domain), or the Max. logon failures on hosts of other domains, they are rejected: the other hosts don't use them (Not tried: ... in the row details), a message is shown and the next scans of the tab (and other tabs with the same account and password) don't use them - set them again with Options > Set Windows credentials.... Computers in a workgroup and local accounts (.\admin) are not part of this check. The checks are written to the log file (without the password).

See Windows account lockout protection for how it works in detail (which results accept or reject the credentials, how failed logons are counted, what is logged and what is not covered).

warning

Every host that answers on port 445 receives a logon with the credentials of the scan (the user running NETworkManager or the Windows credentials of the profile / group / tab) - also a device you don't control. If it is asked by its IP address, the logon uses NTLM: a malicious host could relay it to another server or try to crack the password offline. Only scan networks you trust with privileged accounts, prefer an account with only the rights you need (logged-on users need admin rights on the host) and require SMB signing on your servers. Hosts asked by their DNS name use Kerberos (see above).

note

The NetApi requests need the firewall rules File and Printer Sharing (SMB-In) on the host, the logged-on users admin rights (e.g. a domain admin or the local administrator), the patch level also the Remote Registry service (disabled by default on Windows clients).

Timeout (ms)​

Timeout in milliseconds of the SMB request and of the NetApi requests of a host (each). NetApi requests that take longer are shown as timed out (if only the remote registry takes longer, the other values are shown without the patch level); they keep running in the background until Windows ends them (for all tabs and repeated scans limited by Max. concurrent Windows host information threads).

Type: Integer [Min 500, Max 30000]

Default: 5000

Max. logon failures​

Logon failures with the Windows credentials on hosts outside the domain of the credentials (e.g. in a trusted domain) before they are rejected and not used for the other hosts, see Windows account lockout protection. A logon failure on a host in the domain of the credentials, or with credentials without domain, rejects them right away. The failures are counted per account for all tabs until NETworkManager is closed.

Type: Integer [Min 1, Max 5]

Default: 2

warning

A domain controller may count one failed logon twice (Kerberos, then NTLM). Keep this value below half of the account lockout threshold of your domain.

Find hosts in the local subnet​

info

Find hosts in the local subnet and Resolve MAC address and vendor both read the neighbor table of Windows (ARP for IPv4, NDP for IPv6), but for different purposes. They can be enabled independently (section ARP / NDP in the settings).

Example: a Windows client with the firewall on is only found with Find hosts in the local subnet; its MAC address is only shown if Resolve MAC address and vendor is enabled as well.

Find hosts in a local subnet that don't answer the ping, a port or NetBIOS by their entry in the neighbor table (ARP for IPv4, NDP for IPv6). To send a packet to a host in a local subnet, Windows has to resolve its MAC address first - and a host answers this request even if its firewall drops everything else (e.g. a Windows client in a public network, a phone, an IoT device). After the probes of a host are finished, its entry is read from the neighbor table: a host whose entry was confirmed (Reachable) is shown as up (Detected by ARP / NDP). No additional packets are sent, except for an entry from earlier traffic: an entry that was not confirmed again yet (Stale), or that was already Reachable before the probes were sent (Windows doesn't resolve it again for them), is resolved again (ARP request / neighbor solicitation) to check if the host is still there.

Type: Boolean

Default: Enabled

note

Only hosts in a subnet of a local network interface can be found this way, hosts behind a router are never in the neighbor table. An answer with the MAC address of the default gateway (proxy ARP, e.g. a router that answers for every address of the subnet) is ignored. A host that leaves the network while its probes are running may still be shown as up.

Resolve MAC address and vendor​

Show the MAC address and vendor of every found host in the MAC address and Vendor columns. It doesn't find hosts - a host that doesn't answer the ping, a port or NetBIOS is only found with Find hosts in the local subnet.

Type: Boolean

Default: Enabled

note

The MAC address is resolved via ARP (IPv4) or NDP (IPv6) from the neighbor cache. If no entry is found there, NetBIOS is used as a fallback. Because ARP and NDP are link-layer protocols, the device must be in the same subnet as the local machine.

Resolve mDNS hostname​

Resolve the mDNS hostname (e.g. macbook.local) of every reachable host: a reverse lookup (PTR) is sent to UDP port 5353 of the host. Answered by Apple devices, Linux (Avahi), Android, printers and many IoT devices that have no DNS (PTR) record. The name is shown in the row details (Hostnames) and used as Hostname if there is no DNS hostname (order: DNS, mDNS, NetBIOS). Like a NetBIOS name, it is not passed to other tools (the IP address is used instead).

Type: Boolean

Default: Disabled

note

Most devices only answer requests from the local subnet. Unreachable hosts are not queried.

Timeout (ms)​

Timeout in milliseconds after which an mDNS request is considered lost.

Type: Integer [Min 100, Max 15000]

Default: 2000

Read web pages​

Read the web page (GET /) of every reachable host with an open port of the Ports below: status code, title, the Server and X-Powered-By headers, the realm of a login prompt (WWW-Authenticate header of a 401 response, e.g. RT-AC68U - routers, cameras and printers often name their model there) the target of a redirect to another host (e.g. https://unifi.local:8443/) and, for https, the TLS certificate: subject, issuer (Self-signed for a self-signed certificate) and the end of the validity ((expired) if it is expired). The title is shown in the Web column (the URL in the tooltip), all values in the Web section of the row details. The ports are tried in the order of the list, the first one that answers is used: https on 443 and 8443, http on 80 and 8080, https and then http on any other port. On ports other than 443 / 8443, the https attempt waits at most 1 second (also with a higher timeout), so a plain http device that doesn't answer the TLS handshake doesn't cost the whole timeout before http is tried. Redirects on the same host (e.g. http to https, / to /login.html) are followed, the values (also the certificate) are those of the last response. If the page has no title, the column shows the realm, the Server header (e.g. nginx) or the redirect target. The values are in the search and the export (WebStatusCode, WebServer, WebPoweredBy, WebRealm, WebRedirectURL, WebCertificateSubject, WebCertificateIssuer, WebCertificateNotAfter, WebCertificateSelfSigned). Web Console in the context menu opens the port (and scheme) that answered.

Type: Boolean

Default: Disabled

note

Only ports that are open in the port scan are requested - the ports must also be in its Ports list. Without the port scan, no web page is read and the setting is disabled. No cookies or credentials are sent, no proxy is used and certificate errors are accepted (the certificate is only read). Every request uses a new connection (Connection: close), so the certificate is also read on a rescan. The request appears in the log of the web server. At most 64 KB of the page are read.

Ports​

Ports whose web page title is read, in the order they are tried (only ports that are open). Ports and port ranges are separated by a semicolon. The button next to the field restores the default.

Type: String

Default: 443; 80; 8443; 8080

Example: 443; 80; 8443; 8080; 5000-5001; 9443

Timeout (ms)​

Timeout in milliseconds of a web request (per port, scheme and redirect).

Type: Integer [Min 100, Max 15000]

Default: 2000

Read the SNMP system information​

Read the name, description and location (sysName, sysDescr, sysLocation) of every IP address with an SNMP GET request to UDP port 161, sent together with the ping, the port scan and the NetBIOS request. A host that answers is shown as up (Detected by SNMP), also if it doesn't answer any other probe (e.g. a switch or printer that blocks ICMP). The values are shown in the row details (SNMP), the name also in the SNMP name column, e.g. to identify switches, printers and access points.

Type: Boolean

Default: Disabled

note

A host with another community usually doesn't answer at all (no value after the timeout); an answer with an error (e.g. noSuchName of SNMP v1) still counts as up. The request is sent to every IP address of the range, also unused ones. Many intrusion detection systems report requests with common communities like public.

SNMP v3 needs credentials, so it is only available with the SNMP version and credentials of a profile or group (not in the settings, the settings file is not encrypted). A discovery request is sent first: every SNMP v3 agent answers it, also without valid credentials, so the host is found anyway. Then the GET request with the user; wrong credentials are answered with an error, shown in the row details (SNMP) and exported as SNMPError (e.g. UnknownUserName, AuthenticationFailed). Each of the two requests waits up to the timeout.

Version​

SNMP version of the request.

Type: NETworkManager.Models.Network.SNMPVersion

Default: V2C

Possible values:

  • V1
  • V2C

Community​

Community of the request.

Type: String

Default: public

warning

The community is saved as plain text in the settings file (not encrypted). Use a read-only community (e.g. public), not one with write access.

Timeout (ms)​

Timeout in milliseconds after which an SNMP request is considered lost.

Type: Integer [Min 100, Max 15000]

Default: 2000

Show notification popup on changes​

Show a notification popup in the bottom-right corner of the primary screen when a repeated scan found changes since the previous scan (see Changes since the last scan; only new hosts like a host that is up, a gone host or a changed MAC address like a host that is down). One notification per scan: up to three changes, one per line with the IP address (and hostname) and the change in its color (e.g. 10.0.0.5 (server) · New, green for new, red for gone, orange for a changed MAC address), otherwise one line per counter (e.g. 5 New, 2 Gone). Not for a scan that was started manually. The header shows the tool, the title the scanned input; the status icon is green for only new hosts, red for only gone hosts, half green / half red for both, orange for a changed MAC address. A click opens the tab of the scan.

Type: Boolean

Default: Enabled

Play sound on changes​

Play a system sound when a repeated scan found changes. Independent of the popup.

Type: Boolean

Default: Disabled

Display duration (seconds)​

Time in seconds the notification popup is shown before it closes automatically.

Type: Integer [Min 3, Max 60]

Default: 10

Max. concurrent host threads​

Maximum number of hosts (IP addresses) that are scanned at the same time. A thread is not an operating system thread, but one host that is pinged, scanned for ports and NetBIOS concurrently.

Type: Integer [Min 1, Max 256]

Default: 128

warning

Every host opens up to Max. concurrent port threads TCP connections at the same time (with the default settings up to 128 × 11 = 1408). Too many simultaneous requests may be detected as a port scan and blocked or rate-limited by a firewall (local, on the network or on the scanned devices) and can overload small routers. If hosts are missing in the result or the network becomes slow during the scan, reduce the number of threads. This will increase the scan time.

Max. concurrent port threads​

Maximum number of ports that are scanned at the same time for each host (IP address). If this is less than the number of ports, the remaining ports are scanned after the first ones are finished, which increases the time per host by the timeout.

Type: Integer [Min 1, Max 32]

Default: 16

warning

Too many simultaneous requests may be detected as a port scan and blocked or rate-limited by a firewall (local, on the network or on the scanned devices). If hosts are missing in the result, reduce the number of threads. This will increase the scan time.

Max. concurrent Windows host information threads​

Maximum number of hosts whose NetApi requests of Read Windows host information run at the same time, for all tabs and repeated scans. The requests are blocking: each one uses its own operating system thread, also after the timeout until Windows ends it (e.g. a host that doesn't answer RPC). A host that doesn't get a free slot within the timeout is shown as timed out. A changed value applies to the next requests, also while requests of a running scan are still waiting.

Type: Integer [Min 1, Max 64]

Default: 16
