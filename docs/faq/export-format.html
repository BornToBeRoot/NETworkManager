Export format

How are the results exported?​

Most tools can export their results with Export... (selected or all results) to a CSV, XML or JSON file. All tools use the same format, so a script can read the exports of every tool the same way. The values are never translated: they are the same in every language.

FileStructure
CSVFirst line with the column names, one line per result. Values are separated by ,
XML<Tool><Types><Type>...</Type></Types></Tool> (e.g. <PingMonitor><PingInfos><PingInfo>), one element per column
JSONArray with one object per result, one key per column

The CSV columns, the XML elements and the JSON keys have the same names and order. The columns are in a logical order: like they are shown in the tool, related values next to each other (e.g. the ping or the web page values of the IP Scanner). A new column is added where it belongs, so a script should read the columns by name (CSV header, XML element, JSON key) instead of by position.

Which results are exported?​

Export... exports what is shown in the result: All exports the results shown (e.g. filtered by the search) in the order shown (sorting, grouping), Selected the selected results in the order shown (not in the order they were selected).

How are the values formatted?​

ValueFormat
Empty valueEmpty in CSV (also in a column with quotes), empty element in XML, null in JSON (e.g. the ping time without a reply). An empty text is "" in CSV and JSON
NumberDecimal point in every language (e.g. 10.5), without a unit. JSON: number
Time / durationNumber in a fixed unit: ping time in milliseconds (e.g. 4), SNTP Offset in seconds and RoundTripDelay in milliseconds, WiFi BeaconInterval in milliseconds and Uptime in seconds, Speed of a network interface in bit/s
Yes / NoTrue / False (CSV), true / false (XML, JSON)
Date and timeyyyy-MM-dd HH:mm:ss.fff (e.g. 2026-11-08 10:15:30.123) in the time shown in the tool: local time, SNTP Lookup in UTC
Status, type, stateEnglish name (e.g. Success, TimedOut, Open, Tcp), several values separated by , (e.g. ICMP, TCP)
MAC addressAA:BB:CC:DD:EE:FF
List (e.g. IP addresses)One value, separated by ; (e.g. 10.0.0.53; 10.0.0.54)

IP Scanner: an empty value (null in JSON) means the value is not available - the probe is disabled or was still running (e.g. export during a scan). An empty text ("" in JSON) means the probe ran, but the host had no value (e.g. Windows values of a host without Windows host information, SNMPError without an error). Ports is an empty array in JSON if no port was found or the port scan is disabled (see PortStatus).

In the CSV file, text that may contain a comma (e.g. hostname, description, comment) is always enclosed in quotes ("), any other value only if it contains a comma, a quote or a line break. A quote in a value is doubled (""), as defined in RFC 4180, e.g. for Import-Csv in PowerShell.

warning

Values are exported as they are, also text from the network (e.g. a web page title or an SNMP description). A value that starts with =, +, - or @ may be run as a formula when the CSV file is opened in a spreadsheet application like Excel - open exports of networks you don't trust as text, or use the JSON / XML export.

The ports of a host in the IP Scanner export are one value in the CSV file with port, protocol and state (Port/Protocol/State, ports separated by ; , e.g. 80/Tcp/Open; 443/Tcp/Closed), one PortInfo element per port in the XML file and an array of objects in the JSON file - both also with the service and description.
