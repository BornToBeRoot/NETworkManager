Breaking Changes​

  • Removed the ThreadPool additional min. threads setting (Settings > General) and the application-wide ThreadPool.SetMinThreads workaround it configured for the IP Scanner and Port Scanner. It's no longer needed now that both scan engines use non-blocking async concurrency instead of blocking calls. #3564
  • Exports (CSV, XML, JSON): the exports of all tools now use the same format, see Export format. Columns may have been reordered (like shown in the tool) or added, and values are formatted the same way in every tool (e.g. numbers without unit and with a decimal point, dates as yyyy-MM-dd HH:mm:ss.fff, MAC addresses as AA:BB:CC:DD:EE:FF, empty values instead of placeholders like -/-). If you process exports with scripts or other tools, check them after the update and read the columns by name instead of by position. The changes of each tool are listed below. #3696
  • Network Interface: the export contains the MAC address (PhysicalAddress) as AA:BB:CC:DD:EE:FF instead of AABBCCDDEEFF, the DHCP lease (DhcpLeaseObtained, DhcpLeaseExpires) as 2026-11-08 10:15:30.123 in every format and language (empty without DHCP), and lists of IP addresses separated by ; instead of ;, like in all exports. The IPv6 link-local address comes before the IPv6 address, like in the details. #3696
  • WiFi: the export contains BeaconInterval (milliseconds, e.g. 102.4) and Uptime (seconds) as numbers instead of text (00:00:00.1024000), like the durations of all exports. The columns of the export are in the order of the grid (SSID, connected, security, frequency, channel, channel width, signal, authentication, encryption, BSSID, vendor, ...) instead of the BSSID first and the values shown in the grid at the end. #3696
  • IP Scanner: the export contains the ping time (Time) as a number of milliseconds (e.g. 4) instead of text (4 ms, -/-). Time, TTL and Bytes are empty without a reply instead of -/- / 0, like in all exports. The columns of the export are grouped by topic instead of new columns being appended at the end: host (IsReachable, DetectedBy, IPAddress, hostnames, MAC address, vendor, role, OS), ping, port scan, NetBIOS, web page, SNMP, Windows host information and the change since the last scan. The ports in the CSV export contain port, protocol and state (80/Tcp/Open; 443/Tcp/Closed) instead of also service and description, which can contain / and ; (JSON / XML unchanged). #3696
  • Port Scanner: the JSON export uses the key State for the port state (like CSV and XML) instead of Status. Scripts that read Status have to be adjusted. #3660
  • Ping Monitor: the export contains the ping time (Time) as a number of milliseconds (e.g. 4) instead of text (4 ms, -/-). Time, TTL and Bytes are empty without a reply instead of -/- / 0, like in all exports. The columns are Timestamp, IPAddress, Hostname, Status, Time, TTL, Bytes (status first, like the ping of the IP Scanner). #3696
  • Traceroute: the export contains the times (Time1 - Time3) as a number of milliseconds (e.g. 4) instead of text (4 ms), empty without a reply instead of -/-, like in all exports. #3696
  • SNTP Lookup: the export contains Offset (seconds) and RoundTripDelay (milliseconds) as numbers with a decimal point (e.g. -0.25) instead of text with the unit (-0.25 s, 10.5 ms), like in all exports. The Offset (also in the grid) uses the sign of NTP: time of the server minus the local time (positive if the local clock is behind), the opposite of before. #3696
  • Firewall: the columns of the export are in the order of the grid: IsEnabled first, the local and remote address before the port (LocalAddresses, LocalPorts, RemoteAddresses, RemotePorts), then Program, InterfaceType, NetworkProfiles and Description. #3696
  • Discovery Protocol: the columns of the export are in the order shown: Management and ChassisId (new) after IPAddress, LocalConnection and LocalInterface (new) at the end. #3696
  • IP Geolocation: the columns of the export are in the order shown: Query (IP address) and Reverse after Currency, then the network (Isp, Org, As, Asname, Hosting, Proxy, Mobile), like the geolocation in the Traceroute export. #3696
  • Neighbor Table: the export contains the MAC address as AA:BB:CC:DD:EE:FF (like it is shown) instead of AABBCCDDEEFF, like in all exports. #3696

What's new?​

  • ARM64 builds are now available. #3538

Run command

  • The Run command (Ctrl+Shift+P) now runs a feature directly, e.g. ping 10.0.0.1, dns borntoberoot.net 1.1.1.1 aaaa, rdap 1.10 asn or rdp @server-01 (profile). It opens in a dialog instead of a flyout, with short aliases (e.g. ping, dns, rdp, ssh, geo, wol), suggestions for recent commands, profiles of the feature and types (Up/Down to select, Tab to complete, Enter to run, Esc to close), and validates the input like the feature does. Only visible features are offered. #3644
  • New run command targets for the Subnet Calculator (subnet 10.0.0.0/24, subnet 10.0.0.0/16 /24 for subnetting, subnet 10.0.0.0/24 10.0.1.0/24 for the wide subnet) and the Lookup (lookup oui 00:11:22, lookup port 22; ssh). #3646
  • New global hotkey to bring the window to the foreground and open the run command (default Ctrl+Alt+P, disabled by default), see Settings > HotKeys. #3646
  • Run command: the Port Scanner needs ports, which can also be names of port profiles, also several and together with ports (e.g. portscan 10.0.0.1 webserver or portscan 10.0.0.1 "DNS (via TCP)";webserver;22, suggested after the host and after a ;). Own history size for the run command (default 20, Settings > General). Tab also completes profiles and port profiles, PageUp/PageDown move the selection by 5 suggestions. #3646
  • Run command dialog redesigned: the icon of the recognized feature, the syntax with the part being typed highlighted, the values as they were understood (e.g. Hosts: borntoberoot.net, Type: AAAA), validation while typing, grouped suggestions with the typed text highlighted, examples and key hints (can be hidden in the settings). The dialog uses more space in a large window. The title bar shows a Run command... box in the center (like the command center of VS Code) instead of the icon. Type only a target (e.g. 10.0.0.1, server-01, 00:11:22:33:44:55, 10.0.0.0/24) to get the commands that accept it, recent commands are also suggested while typing (e.g. a host); optionally, a target in the clipboard is suggested (Settings > General). Ctrl+Enter runs and keeps the dialog open, Shift+Enter fills in the input without starting, Shift+Del or the remove button removes a recent command. #3646

Settings

  • New global DNS suffix options in Settings > Network: Add DNS suffix (primary) to hostname appends the Windows primary (or, if none is set, the active network adapter's connection-specific) DNS suffix to a bare hostname before resolving it, and Use custom DNS suffix lets you override it with a suffix of your own. Previously only available in DNS Lookup, this now also applies to every other tool that resolves hostnames through NETworkManager's shared DNS resolver (e.g. Ping, Traceroute, Port Scanner, IP Scanner, SNTP Lookup) — DNS Lookup stays independent. #3591
  • DNS server(s) in Settings > Network is now a list of servers (IP address + port), configured via an Edit DNS server dialog, replacing the previous single semicolon-separated, port-53-only text field. #3591

WiFi

  • Changes since the last scan: each scan is compared with the previous scan of the same adapter (by BSSID). The new column Since last scan shows networks that are New, Gone (shown faded until the next scan) or Changed (channel, channel width or security, the tooltip shows the previous values), the header shows the counters (e.g. 2 New · 1 Gone). Also in the search and the export (Change). Useful with Automatically update every to see new access points or channel changes. #3695
  • Notification for changes: when Automatically update every finds new, gone or changed networks, a notification popup (and optionally a sound) shows them, like the IP Scanner. Configurable in the new WiFi settings (Show notification popup on changes, Play sound on changes, Display duration). #3695

Traceroute

  • New Map view below the hop list, visualizing each resolved hop's geolocation on an offline world map. Consecutive hops are connected with curved, directional arrows; hovering a marker shows its location, ISP/ASN, hostname, IP address and average round-trip time, while hovering an arrow shows the source and destination location of that segment. The map supports mouse-wheel zoom and drag-to-pan, and can be collapsed via a toggle button on the map itself, similar to the Profiles panel. The map is only shown if Check IP geolocation and the new Show map setting are both enabled, since hops need a resolved geolocation to be plotted. #3520

RDAP

  • New RDAP tool to look up registration data via the Registration Data Access Protocol, the standardized, JSON-based successor of Whois. Supports domains, nameservers, top-level domains, IP addresses/CIDR prefixes, AS numbers and entity handles; the type is detected automatically or can be selected. The RDAP server is determined automatically using the IANA bootstrap files, which are cached locally and can be updated in the new Settings > RDAP page. Results are shown in a structured view (details, status, events, nameservers, DNSSEC, networks and AS numbers of an organization, contacts, notices) or as raw JSON, and can be exported as JSON or text. For domains (e.g. .com/.net), the referral to the registrar's RDAP server is followed as well (can be disabled in Settings > RDAP). Includes profile support. If no RDAP server is known for a domain, it can be opened in Whois with a single click. IP addresses and hostnames can be queried from the context menu of IP Scanner and Traceroute, AS numbers from Traceroute; for a hostname (e.g. www.borntoberoot.net), the registered domain is queried (determined with the included Public Suffix List). #3607 #3642

  • Added a port status icon column to the results, matching the port icon used in the IP Scanner's extended port info, to indicate at a glance whether a port is open (green) or closed (red). #3558
  • Added a live count of ports open/closed below the Result header. Stays visible after the scan finishes. #3572

Dependencies, Refactoring & Documentation​

  • Code cleanup & refactoring
  • Dependabot updates the NuGet packages again (no updates since February 2025). The Windows SDK version is now set via TargetPlatformVersion instead of in the target framework (net10.0-windows10.0.22621.0 → net10.0-windows), which Dependabot can't handle (dependabot-core#13278). The build output moved from bin\...\net10.0-windows10.0.22621.0\ to bin\...\net10.0-windows\. 1ce8310
  • Context menus of lists (results, profiles, settings) get the view model in XAML instead of when they are opened. Their items, and menu items that are created outside of a menu (e.g. the extra items of the profile context menu), no longer cause XAML binding errors every time a list is filled, which hid real binding errors.
  • Converted the IP Scanner and Port Scanner engines from Parallel.ForEach with blocking calls to genuinely asynchronous Parallel.ForEachAsync, removing the risk of exhausting the application's ThreadPool at high concurrency settings. #3564
  • The TCP port probe (IP Scanner, Port Scanner) and the NetBIOS request (IP Scanner) report a refused connection, a timeout or no answer as result instead of throwing an exception for each of them (thousands per scan). Faster, and the application no longer lags while scanning with a debugger attached. #3653
  • Refactored the Network Connection widget's check logic to reduce duplicated code and share the local IP address detection between the Computer and Router checks instead of detecting it twice. #3553
  • Consolidated the duplicated Profiles side panel (search, tag filter, grouped list, context menu, add/edit/copy/delete) used across 15 tool views into a single shared control, reducing code duplication. As part of this, the profile panel's expanded/width state is now shared across all tools instead of being tracked per tool. #3537
  • Replaced the internal event system for opening a feature with data (e.g. Open in RDAP from the IP Scanner) with typed requests, which can also carry options (e.g. DNS server and record type) and profiles. Features no longer fail to open from another feature while the application list is filtered by a search. #3644
  • Input histories (e.g. hosts, domains, ports) are updated in place instead of being cleared and refilled, which avoids clearing the text of the input field and unnecessary updates. #3644
  • Added a unit test project (xUnit) with tests for the run command parser and the history lists. #3644
  • Reworked the GitHub issue templates as forms (bug report, feature request, question) that ask for the relevant information (e.g. affected feature, version, installation, Windows version, log), with links to the documentation, discussions, translations and security advisories. Simplified the pull request template and removed the Copilot summary section. #3660
  • Faster CI: AppVeyor no longer builds a branch a second time when a PR is open, skips changes that only affect the documentation / website, builds ARM64 only for releases and now runs the unit tests. The website is only built for PRs that change it and builds about 3x faster (Docusaurus Faster). Dependabot also updates the GitHub Actions, and CodeQL also scans the workflows. Website changes are only merged automatically if the website builds. Dependabot major updates are no longer merged automatically. Removed the stale bot. #3675
  • The exports (CSV, XML, JSON) of all tools define their columns once and are written by one shared writer, so the three formats can't drift apart and every tool formats the same kind of value the same way (not translated), see Export format. Added unit tests for the exports. #3696
