System requirements

  • Windows 10 / Server x64/ARM64 (22H2 or later)
  • .NET Desktop Runtime 10.0 (LTS) - x64/ARM64

Breaking Changes​

  • Removed the ThreadPool additional min. threads setting (Settings > General) and the application-wide ThreadPool.SetMinThreads workaround it configured for the IP Scanner and Port Scanner. It's no longer needed now that both scan engines use non-blocking async concurrency instead of blocking calls. #3564
  • Port Scanner: the JSON export uses the key State for the port state (like CSV and XML) instead of Status. Scripts that read Status have to be adjusted. #3660

What's new?​

  • ARM64 builds are now available. #3538

Run command

  • The Run command (Ctrl+Shift+P) now runs a feature directly, e.g. ping 10.0.0.1, dns borntoberoot.net 1.1.1.1 aaaa, rdap 1.10 asn or rdp @server-01 (profile). It opens in a dialog instead of a flyout, with short aliases (e.g. ping, dns, rdp, ssh, geo, wol), suggestions for recent commands, profiles of the feature and types (Up/Down to select, Tab to complete, Enter to run, Esc to close), and validates the input like the feature does. Only visible features are offered. #3644
  • New run command targets for the Subnet Calculator (subnet 10.0.0.0/24, subnet 10.0.0.0/16 /24 for subnetting, subnet 10.0.0.0/24 10.0.1.0/24 for the wide subnet) and the Lookup (lookup oui 00:11:22, lookup port 22; ssh). #3646
  • New global hotkey to bring the window to the foreground and open the run command (default Ctrl+Alt+P, disabled by default), see Settings > HotKeys. #3646
  • Run command: the Port Scanner needs ports, which can also be names of port profiles, also several and together with ports (e.g. portscan 10.0.0.1 webserver or portscan 10.0.0.1 "DNS (via TCP)";webserver;22, suggested after the host and after a ;). Own history size for the run command (default 20, Settings > General). Tab also completes profiles and port profiles, PageUp/PageDown move the selection by 5 suggestions. #3646
  • Run command dialog redesigned: the icon of the recognized feature, the syntax with the part being typed highlighted, the values as they were understood (e.g. Hosts: borntoberoot.net, Type: AAAA), validation while typing, grouped suggestions with the typed text highlighted, examples and key hints (can be hidden in the settings). The dialog uses more space in a large window. The title bar shows a Run command... box in the center (like the command center of VS Code) instead of the icon. Type only a target (e.g. 10.0.0.1, server-01, 00:11:22:33:44:55, 10.0.0.0/24) to get the commands that accept it, recent commands are also suggested while typing (e.g. a host); optionally, a target in the clipboard is suggested (Settings > General). Ctrl+Enter runs and keeps the dialog open, Shift+Enter fills in the input without starting, Shift+Del or the remove button removes a recent command. #3646

RDAP

  • New RDAP tool to look up registration data via the Registration Data Access Protocol, the standardized, JSON-based successor of Whois. Supports domains, nameservers, top-level domains, IP addresses/CIDR prefixes, AS numbers and entity handles; the type is detected automatically or can be selected. The RDAP server is determined automatically using the IANA bootstrap files, which are cached locally and can be updated in the new Settings > RDAP page. Results are shown in a structured view (details, status, events, nameservers, DNSSEC, networks and AS numbers of an organization, contacts, notices) or as raw JSON, and can be exported as JSON or text. For domains (e.g. .com/.net), the referral to the registrar's RDAP server is followed as well (can be disabled in Settings > RDAP). Includes profile support. If no RDAP server is known for a domain, it can be opened in Whois with a single click. IP addresses and hostnames can be queried from the context menu of IP Scanner and Traceroute, AS numbers from Traceroute; for a hostname (e.g. www.borntoberoot.net), the registered domain is queried (determined with the included Public Suffix List). #3607 #3642

Traceroute

  • New Map view below the hop list, visualizing each resolved hop's geolocation on an offline world map. Consecutive hops are connected with curved, directional arrows; hovering a marker shows its location, ISP/ASN, hostname, IP address and average round-trip time, while hovering an arrow shows the source and destination location of that segment. The map supports mouse-wheel zoom and drag-to-pan, and can be collapsed via a toggle button on the map itself, similar to the Profiles panel. The map is only shown if Check IP geolocation and the new Show map setting are both enabled, since hops need a resolved geolocation to be plotted. #3520

Settings

  • New global DNS suffix options in Settings > Network: Add DNS suffix (primary) to hostname appends the Windows primary (or, if none is set, the active network adapter's connection-specific) DNS suffix to a bare hostname before resolving it, and Use custom DNS suffix lets you override it with a suffix of your own. Previously only available in DNS Lookup, this now also applies to every other tool that resolves hostnames through NETworkManager's shared DNS resolver (e.g. Ping, Traceroute, Port Scanner, IP Scanner, SNTP Lookup) — DNS Lookup stays independent. #3591
  • DNS server(s) in Settings > Network is now a list of servers (IP address + port), configured via an Edit DNS server dialog, replacing the previous single semicolon-separated, port-53-only text field. #3591

Improvements​

  • Links (e.g. in About, Web Console and the notices in RDAP) are now keyboard accessible: they can be reached with Tab and opened with Enter. #3607
  • Actions that require elevated rights now show a tooltip with the reason when they are disabled because the application is not running as administrator (e.g. Apply, Flush DNS cache and Release & Renew in Network Interface, the context menu and Add entry... in Hosts File Editor, Firewall and Neighbor Table, and Capture in Discovery Protocol). #3626
  • The collapsed/expanded state of profile groups (e.g. linux-server) is now remembered per profile file and shared across all tools, instead of resetting every time you switch tools or restart the application. #3539

NETworkManager has to run elevated (Restart as Administrator, confirm with your own credentials). The hint is now also shown as tooltip on Apply in the profile context menu. #3606

IP Scanner

Max. concurrent host threads is lowered from 256 to 128 (max. 256 instead of 512) to put less simultaneous load on the network. An empty /24 network is scanned in about 8 seconds instead of about 50. Settings that are still on the old default are updated. #3564 #3653
  • The neighbor table (ARP/NDP) is read once and cached during a scan instead of once per reachable host to resolve the MAC address. The MAC address of the own IPv6 addresses and of IPv6 link-local neighbors is resolved as well. #3653
  • Resolve MAC address and vendor is enabled by default for new installations (as documented). #3653
  • The export runs in the background, so the window stays responsive while a large result is exported, and uses the order shown in the result (sorting) instead of the order in which the hosts were scanned. #3653
  • The DNS hostname and the MAC address of a host are resolved at the same time instead of one after the other. #3660
  • New Expand host view setting to show the details of every host in the result (also hosts added while the scan is running), like in the Ping Monitor. #3660
  • The up / down counter next to the Result header is translated as one text, so translations can put the number in a different position. #3660
  • Rescan in the context menu scans the selected host(s) again with the settings of the shown scan and updates their rows, e.g. to check if a host is up again. #3660
  • Added Web Console (https / http depending on the open ports) and Wake on LAN (with the MAC address) to the context menu. #3660
  • Added a search box above the result to filter the hosts by IP address, hostname, MAC address, vendor and open ports, also while the scan is running. #3660
  • Copy > IP address / Hostname / MAC address is also available if multiple results are selected (one value per line, in the order shown). #3660
  • Added a Time column with the round trip time of the ping. Sorted by time, hosts without a ping reply are at the end. #3660
  • A host is shown as soon as it answers (ping reply, open or refused port or NetBIOS answer) instead of after all probes and lookups are finished (up to the port scan / NetBIOS timeout, plus the DNS lookup). Values of probes that are still running are shown as ..., the other results, the DNS hostname and the MAC address / vendor are filled in when they arrive. The DNS hostname and the MAC address are resolved right after the first answer. #3660
  • The CSV and XML export contain the DNS hostname (DNSHostname) in addition to the hostname (DNS, or NetBIOS as fallback), like the JSON export. It is added as last column (CSV) / element (XML), so the position of the other columns doesn't change. #3660
  • Hosts are started one after another (every 10 ms, shorter with short timeouts and many threads) instead of all at the same moment. This avoids bursts of more than a thousand connection requests within a few milliseconds and makes the progress smoother. #3653
  • Closed ports are reported immediately. Windows repeated the connection request after the host refused it and reported a closed port only after about 2 seconds. The connection request is sent once. #3653
  • New Attempts setting for the port scan (default 1): another connection request is sent if there was no answer, e.g. on an unreliable network (Wi-Fi, VPN) or for hosts on the internet. Open and closed ports are not repeated. #3653
  • Added RDAP... to the context menu to query the registration data of the IP address or hostname of a host in the RDAP tool. #3642

Settings that are still on the old default are updated. #3564 #3653
  • Closed ports are reported immediately. Windows repeated the connection request after the host refused it and reported a closed port only after about 2 seconds, so a scan of a host that refuses most ports is much faster now (e.g. 1-1024: about 1 second instead of about 16 seconds). The connection request is sent once. #3653
  • New Attempts setting (default 1): another connection request is sent if there was no answer, e.g. on an unreliable network (Wi-Fi, VPN) or for hosts on the internet. Open and closed ports are not repeated. #3653

The context menu of a host also opens it in other tools, adds it as a profile and copies its IP address, hostname or open ports (e.g. 22; 80; 443). #3660
  • Added Web Console to the context menu of an open web port (80, 443, 8080, 8443). #3660

  • Profiles: the Ports of the Port Scanner can contain port profiles (selectable in the list like in the tool), which are referenced by the profile - changes to a port profile apply, also after a rename.   • Port profiles can be entered by name in the Ports input, also several and together with ports (e.g. Webserver; Database; 8080, case-insensitive). The name of a port profile must be unique, must not contain ; (replaced by , when updating) and must not be a port or port range. #3660
  • Added Add profile... to the context menu: creates a profile with the host (IP address), the hostname as name and the ports of the shown scan. #3660
  • Several port profiles can be selected in the settings and deleted at once (context menu or Del), the confirmation lists them. #3660
  • Added a search box above the result to filter the ports by IP address, hostname, port, protocol, service, description and status, also while the scan is running. #3660
  • Copy > IP address / Hostname / Port / IP address:Port is available if multiple results are selected (one value per line, in the order shown). #3660
  • New setting Ping hosts before the scan (default off): only hosts that answer a ping are scanned, the number of skipped hosts is shown after the scan. Faster for ranges with many unused IP addresses; hosts that block ICMP are skipped. #3660
  • New setting Adjust threads automatically (default on): the number of hosts and ports scanned at the same time is adjusted to the scan (up to 512 connections, at most 128 hosts and 128 ports per host). A scan with few ports is much faster, e.g. a /24 with one port (e.g. 3389) takes about 4 seconds instead of about 2 minutes; 1-1024 is unchanged. Max. concurrent host threads (now up to 256) and Max. concurrent port threads are used if it is disabled, with at most 8,192 connections at the same time. It is disabled when updating if the threads were changed. The hostname (DNS PTR) of a host is resolved when its first port is scanned, so the lookups are spread over time like the ports. #3660

  • Ports are started one after another (every 1 ms, shorter with short timeouts and many threads) instead of all at the same moment. This avoids bursts of hundreds of connection requests within a few milliseconds and makes the progress smoother. #3653

Dependencies, Refactoring & Documentation​

  • Code cleanup & refactoring
  • Converted the IP Scanner and Port Scanner engines from Parallel.ForEach with blocking calls to genuinely asynchronous Parallel.ForEachAsync, removing the risk of exhausting the application's ThreadPool at high concurrency settings. #3564
  • The TCP port probe (IP Scanner, Port Scanner) and the NetBIOS request (IP Scanner) report a refused connection, a timeout or no answer as result instead of throwing an exception for each of them (thousands per scan). Faster, and the application no longer lags while scanning with a debugger attached. #3653
  • Refactored the Network Connection widget's check logic to reduce duplicated code and share the local IP address detection between the Computer and Router checks instead of detecting it twice. #3553
  • Consolidated the duplicated Profiles side panel (search, tag filter, grouped list, context menu, add/edit/copy/delete) used across 15 tool views into a single shared control, reducing code duplication. As part of this, the profile panel's expanded/width state is now shared across all tools instead of being tracked per tool. #3537
  • Replaced the internal event system for opening a feature with data (e.g. Open in RDAP from the IP Scanner) with typed requests, which can also carry options (e.g. DNS server and record type) and profiles. Features no longer fail to open from another feature while the application list is filtered by a search. #3644
  • Input histories (e.g. hosts, domains, ports) are updated in place instead of being cleared and refilled, which avoids clearing the text of the input field and unnecessary updates. #3644
  • Added a unit test project (xUnit) with tests for the run command parser and the history lists. #3644
  • Reworked the GitHub issue templates as forms (bug report, feature request, question) that ask for the relevant information (e.g. affected feature, version, installation, Windows version, log), with links to the documentation, discussions, translations and security advisories. Simplified the pull request template and removed the Copilot summary section. #3660
  • Language files updated via #transifex
  • Dependencies updated via #dependabot
